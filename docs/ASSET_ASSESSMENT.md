# ONER-3D — Asset Feasibility Assessment (Three.js-only)

> Status: **planning document.** Nothing downloaded, nothing modified.
> Supersedes the Blender-dependent sections of `ASSET_PIPELINE.md`.
>
> **Constraint: the website must run on Three.js + React Three Fiber alone.
> Blender is optional and offline-only, used solely if a specific asset proves
> impossible to prepare with web tooling.**

All findings below were verified by querying the Poly Haven API and inspecting
the actual `.gltf` manifests — not from memory or documentation.

---

## 0. Headline

**Roughly 85% of the project is achievable with no Blender at all.**

Every asset listed in §2–§5 downloads as glTF 2.0 with standard PBR maps and
loads directly in Three.js. The blockers are narrow, and only two of them
genuinely need a non-web tool.

`gltf-transform` (pure JS/WASM, runs in Node) handles decimation, welding,
quantization, LOD generation, and Meshopt compression. `sharp` handles
resizing, format conversion, and atlas composition. Together they cover
everything the Blender plan called for — **except** KTX2 texture compression
and true vertex-colour AO baking.

---

## 1. Critical findings from API inspection

These changed the plan and are worth stating plainly.

### 1.1 Poly Haven ships **no GLB** — glTF + external textures only

`files/<id>` returns `blend`, `fbx`, `gltf`, `usd`. No `glb` key on any asset
checked. Not a problem: the glTF + `.bin` + JPEG set loads fine via
`GLTFLoader`, and `gltf-transform` merges to GLB in one command.

### 1.2 **`lods: true` in the API does NOT mean LODs ship in the glTF**

This is the important one. `info/<id>.lods` is true for many assets, but
inspecting the manifest for `jacaranda_tree` shows **one mesh with three
primitives** (branches / trunk / leaves) and no LOD extension. Those three
primitives are *material groups*, not LODs.

**So the LOD chains must be generated by us.** `gltf-transform` can do this
with `meshoptimizer`'s simplifier. No Blender required — but it is work we own.

### 1.3 Polycounts are wildly inconsistent with the manifest

`jacaranda_tree` reports 312,356 polys, but the manifest has **3,680,496
vertices** and a **198 MB** buffer — because the leaves are 2.6M vertices of
individual leaf cards. At that size it is completely unusable in a web scene
without simplification.

This means the reported polycount is close to meaningless as a budget
indicator. Vertex count and buffer size are the real numbers. Several assets
also carry redundant `COLOR_0` / `COLOR_1` attributes that `gltf-transform`
can strip.

### 1.4 Textures are already 1K–8K PBR, and small at 1K

Poly Haven's glTF path serves **1K textures by default**, and they are
genuinely small: `fern_02` is 1.1 MB total, `modular_pipes` 5.4 MB,
`island_tree_02` 44 MB. The 8K/16K sources exist but are unnecessary — 8K is
for offline renderers, and shipping 8K is actively harmful on Arc.

**This removes most of the argument for a Blender atlas pass.** Poly Haven's
1K PBR sets are already web-appropriate.

### 1.5 AO is available as an explicit texture channel

Many assets ship a separate `*_ao_*.jpg`. That is a **material input
Three.js consumes directly** — no baking required. For trees and props this is
good enough. Vertex-colour AO baking remains valuable only for the factory.

### 3.1 The five genuine gaps

These have **no CC0 equivalent** — I searched specifically. They are the
superstructure that makes a site read as heavy industry.

| Missing | Why it matters | Web-tooling option | Verdict |
| --- | --- | --- | --- |
| **Chimney stack** | The camera flies to it at 0.20–0.32. It is the single most important object in the project | Lathe/revolve geometry authored in code + `modular_industrial_pipes_01` banding | **No Blender** — build procedurally with a real brick/rust material |
| **Storage tanks** | Signature industrial silhouette | `CylinderGeometry` + conical roof + `modular_fire_escape` spiral stair | **No Blender** — same approach |
| **Cooling tower** | Reads unmistakably as heavy industry | Hyperboloid `LatheGeometry` from a profile curve | **No Blender** |
| **Conveyor bridge** | The defining feature in the reference images | Truss from instanced beams; span is parametric | **No Blender** — but this is the weakest of the four without a modeller |
| **Structural truss frame** | Ties the buildings together | Parametric lattice, instanced | **No Blender** — same caveat |

This is a much better position than the earlier plan assumed. **Procedural
geometry is appropriate here precisely because these are not hero-detail
objects at close range** — the camera never gets within ~80 m of a tank. What
they need is correct silhouette, scale, and *real weathered materials*, not
geometric micro-detail. The materials come from Poly Haven PBR; the form comes
from `LatheGeometry` and instanced beams.

The conveyor bridge is the one I would revisit if the result looks thin, and
that is where optional Blender would first earn its place.

## 6. What still needs a non-web tool — and whether it matters

| Task | Web tooling | Gap | Impact if deferred |
| --- | --- | --- | --- |
| LOD chain generation | `gltf-transform simplify` (meshoptimizer, WASM) | None | **None — this is the plan** |
| Vertex welding / dedup | `gltf-transform weld` | None | None |
| Strip unused attributes | `gltf-transform prune` | None | None |
| Quantization | `gltf-transform quantize` | None | None |
| Meshopt compression | `gltf-transform meshopt` | None | None — and preferable to Draco on Arc |
| Texture resize / convert | `sharp` (prebuilt binaries) | None | None |
| Texture atlas packing | `sharp` composite | Awkward but possible | Low — Poly Haven 1K sets already work |
| Desaturate jacaranda | `sharp` modulate | None | None |
| **KTX2 / BC7 compression** | ✗ needs `toktx` (KTX-Software) | **Yes** | **Medium.** JPG textures cost ~4× the VRAM of BC7. With 16 GB shared this is the real pressure point. Three alternatives below |
| **Vertex-colour AO bake** | ✗ needs a renderer | **Yes** | **Low.** Explicit AO textures cover most surfaces |

### On KTX2 — three ways forward, no install required

1. **Ship JPG/WebP and manage the budget.** WebP via `sharp` is ~30% smaller
   than JPG and universally supported. Constrain total texture memory to
   ~250 MB by choosing resolution per role. **This is the pragmatic default.**
2. **Prefer pre-compressed sources.** ambientCG and Poly Haven both serve
   KTX2/Basis variants on their CDNs for some assets. Worth checking per-asset
   before assuming we must convert.
3. **Optional portable `toktx`.** KTX-Software ships a standalone Windows
   binary — no install, drop it in `tools/`. Only if measurement shows we need
   it. This is the *first* candidate for the optional-Blender-grade toolchain
   rule, and it is far lighter than Blender.

## 9. Canopy shell — the highest-leverage item

At 620 m the camera looks *down at canopy tops*; individual trees are ~8 px.
Rendering thousands of them is both expensive and less accurate than rendering
the forest *volume*.

| Property | Value |
| --- | --- |
| Geometry | 2 displaced shells on the heightfield, ~30k tris |
| Texture | 2K alpha-tested canopy, tiled, authored in the shader |
| Silhouette | ~400 billboard cards breaking the outline |
| Blend | Depth-aware, front-to-back |
| Band | 900 m – 3 km |

Perceived density becomes nearly free. Built in Milestone 1 because it is the
item most likely to look wrong.

## 11. Where Blender would genuinely help — deferred, not required

If measurement later shows a shortfall, in priority order:

1. **Vertex-colour AO bake** for the factory. Contact darkening for free at
   runtime. Currently covered by AO textures.
2. **Conveyor bridge truss authoring.** The one geometry in §3.1 with no good
   procedural answer.
3. **Impostor atlas render** — 4 render angles baked to a texture atlas.
   Currently: single billboard per tree at LOD2.
4. **Texture atlas repack** if draw calls become the bottleneck.

None blocks the project. All are quality refinements.

## 12. Unavoidable compromises

1. **The best photoreal tree packs are paid.** Forestation / Terra Scans are
   $30–40. Unavailable. This is the largest single gap versus the reference.
2. **Photogrammetry industrial assets do not exist free.** The factory will be
   a high-quality modular assembly, not a scan.
3. **At 620 m the factory reads as a well-made model.** Aerial long-lens
   compression is not reproducible with geometry.
4. **Cinematic, not photographic.** On Arc integrated graphics this is the
   honest ceiling.
5. **JPG textures cost ~4× the VRAM of BC7** unless we take the optional
   `toktx` route. Managed by a hard memory budget instead.
6. **Expected 30–50 fps**, dips during scroll, absorbed by adaptive resolution.
7. **No SSR, no TAA, no volumetric light shafts.** Unaffordable here.
8. **Smoke is particles, not true volumetrics.**
9. **No water reflection of the factory.** The lake will not mirror the plant
   as the reference does.
10. **`moss_01` may be unusable as shipped** — geometry-nodes scatter baked
    into the file. Needs inspection.

---

## 13. Verdict

**Proceed Three.js-first.** No Blender installation is needed to start, and the
majority of the project never needs one.

Revised Milestone 1:

1. `gltf-transform` + `sharp` asset pipeline
2. **Canopy shell** — highest risk, first
3. Two tree species with LOD chains generated by `gltf-transform simplify`
4. Terrain with splat-mapped PBR + explicit AO
5. HDRI environment lighting via `RGBELoader` + `PMREMGenerator`
6. Shadow cascades
7. Keep quality tiers, adaptive scaling, scroll, timeline, validators

**Milestone 2:** factory assembly from §3 plus the five procedural
superstructure pieces, on the existing levelled pad.
